# 마이링크 (MyLink) — 1단계 프로필 페이지 PRD

---

## 1. 프로젝트 및 시연 개요 (Overview)

- **서비스명**: 마이링크 (MyLink)
- **현재 단계**: **1단계 — 로컬 스토리지 기반 프로필 페이지 구현** (시연용 MVP)
- **목표**: 
  - 대시보드나 복잡한 통계 기능 없이, **로컬 스토리지(`localStorage`)와 연동된 단일 프로필 페이지**를 먼저 완성합니다.
  - 정적으로 하드코딩된 화면을 탈피하여, 브라우저 저장소에서 데이터를 동적으로 읽어오고 수정·추가할 수 있는 실감 나는 시연 환경을 제공합니다.
- **디자인 아이덴티티**: 당근 **SEED Design System** 기반 (`design.nd`의 Carrot 주황 포인트, 둥근 모서리, 정갈한 카드 레이아웃)

## 3. 사용자 시나리오 (User Scenarios)

### 3.1. 방문자(Visitor) 시나리오
> 소유자의 공유 URL을 통해 마이링크 페이지를 처음 방문한 사용자의 행동 흐름

1. **페이지 진입**: 사용자는 프로필 소유자의 다양한 작업물과 활동 채널을 한눈에 확인하기 위해 공유된 마이링크 링크(URL)를 클릭하여 접속한다.
2. **프로필 및 정체성 인지**: 사용자는 이 페이지의 주인이 누구이며 어떤 역할을 하는 사람인지 빠르게 파악하기 위해 화면 상단의 프로필 아바타, 이름, 직무 뱃지(예: 주니어 웹 개발자), 한 줄 소개글을 읽는다.
3. **기술 스택 및 역량 확인**: 사용자는 소유자의 관심 분야와 주요 사용 기술을 한눈에 훑어보기 위해 소개글 하단에 배치된 기술 스택 칩(Next.js, React 등)을 확인한다.
4. **대표 액션 링크 탐색**: 사용자는 소유자가 가장 강조하고 있는 메인 활동(예: 대표 깃허브 저장소)을 먼저 둘러보기 위해 최상단에 당근 주황색으로 강조된 대표 액션 버튼(Action Button)을 클릭한다.
5. **세부 프로젝트 탐색**: 사용자는 포트폴리오 모음, 블로그, 다른 작업물 등 추가적인 정보를 살펴보기 위해 아래로 스크롤하며 부드러운 카드 형태의 리스트 아이템들을 탐색한다.
6. **목적지 이동**: 사용자는 관심이 가는 특정 프로젝트의 세부 내용을 열람하기 위해 해당 링크 카드를 탭하여 새로운 브라우저 탭으로 이동한다.

### 3.2. 소유자(Owner) 시나리오
> 자신의 프로필과 링크를 최신 상태로 유지하고 시연을 진행하는 사용자의 행동 흐름

1. **관리 모드 전환**: 사용자는 내 프로필과 링크 목록을 편집하기 위해 마이링크 페이지 하단/우측 상단에 위치한 `[편집 모드]` 버튼을 클릭한다.
2. **프로필 정보 최신화**: 사용자는 최근 변경된 상태나 새로운 다짐을 프로필에 반영하기 위해 이름, 직무 뱃지 문구, 한 줄 소개 입력창을 클릭하여 텍스트를 수정한다.
3. **새 링크 추가**: 사용자는 최근 완성한 새 프로젝트를 방문자들에게 알리기 위해 `[+ 새 링크 추가]` 버튼을 눌러 입력 카드를 생성하고, 프로젝트 제목과 URL을 입력한다.
4. **기존 링크 내용 수정**: 사용자는 기존에 등록된 링크의 설명 문구를 더 매력적이고 직관적으로 다듬기 위해 해당 링크 카드의 텍스트 영역을 클릭하여 내용을 인라인으로 편집한다.
5. **링크 노출 여부 토글 (On/Off)**: 사용자는 점검 중이거나 일시적으로 방문자에게 보여주고 싶지 않은 링크를 비공개 처리하기 위해 해당 링크 카드의 `[활성화 스위치]`를 꺼서 숨김 상태로 전환한다.
6. **오래된 링크 삭제**: 사용자는 더 이상 유효하지 않거나 필요 없어진 오래된 링크를 정리하기 위해 해당 링크 카드의 `[삭제]` 아이콘을 클릭하여 리스트에서 제거한다.
7. **저장 완료 및 영속성 확인**: 사용자는 편집한 내용이 로컬 스토리지에 안전하게 보존되고 방문자에게 어떻게 보일지 최종 검증하기 위해 `[편집 완료]`를 누르고 페이지를 새로고침하여 반영 결과를 확인한다.
8. **시연 초기화 (Reset)**: 사용자는 시연 발표나 튜토리얼을 마친 후 깨끗한 초기 상태로 되돌리고자 `[기본값 복원]` 버튼을 눌러 초기 시드 데이터(`src/data/mock-links.json`)로 리셋한다.

## 5. 1단계 핵심 기능 요구사항 (Phase 1 Scope)

### 5.1. 로컬 스토리지 기반 데이터 연동 (Data Persistence)
- **초기 시드 데이터 자동 로드 (`src/data/mock-links.json`)**:
  - 로컬 스토리지에 저장된 데이터가 없을 경우, `src/data/mock-links.json`에 정의된 더미데이터를 읽어와 초기 상태로 자동 주입.
- **실시간 저장**:
  - 프로필이나 링크 수정 시 브라우저 `localStorage`에 즉시 반영되어 페이지를 새로고침해도 변경 사항이 유지됨.
- **기본값 초기화 버튼**:
  - 시연 중 언제든 `src/data/mock-links.json`의 원본 데이터로 되돌릴 수 있는 '초기화(Reset)' 버튼 제공.

### 5.2. 프로필 영역 (Profile Section)
- **표시 항목**:
  - 아바타 (이니셜 '이' 원형 아이콘) + 온라인 상태 인디케이터
  - 이름: "이지환"
  - 직무 뱃지: "주니어 웹 개발자" (SEED Badge 스타일)
  - 소개글: "아이디어를 코드로 구현하는 것을 즐기는 개발자입니다..."
  - 기술 스택 칩: Next.js, React, TypeScript, Tailwind CSS, Vibe Coding
- **간편 편집 모드**:
  - 시연 시 편집 모드를 켜서 이름, 소개글, 직무를 제자리에서 변경 가능.

### 5.3. 링크 리스트 영역 (Links Section)
- **링크 동적 표시**:
  - `isActive === true`인 활성화된 링크만 깔끔하게 노출.
  - 대표 링크: SEED Action Button (당근 주황색 솔리드 버튼)
  - 서브 링크: SEED List Item (아이콘 + 제목 + 설명 + 우측 꺾쇠)
- **간편 링크 조작 (시연용 컨트롤)**:
  - **새 링크 추가**: 제목과 URL을 입력하여 새 버튼 추가
  - **링크 On/Off 토글**: 특정 링크 숨기기/보이기
  - **링크 삭제**: 불필요한 링크 제거

## 6. 데이터 스키마 및 더미데이터 명세

### 6.1. 데이터 스키마 (`src/types/link.ts`)

```typescript
export interface LinkItem {
  id: string;            // 고유 식별자 (예: link-1)
  title: string;         // 링크 제목 (예: GitHub 저장소)
  url: string;           // 이동 링크 URL
  description?: string;  // 부가 설명 문구
  isActive: boolean;     // 노출 활성화 여부 (On/Off)
  isPrimary?: boolean;   // 메인 대표 링크 여부
  icon?: string;         // 아이콘 식별자 (예: github, folder, code)
  order: number;         // 정렬 순서
}

export interface UserProfile {
  username: string;      // 사용자 식별자 (예: 07ez)
  name: string;          // 표시 이름 (예: 이지환)
  title: string;         // 직무 뱃지 (예: 주니어 웹 개발자)
  bio: string;           // 한 줄 소개글
  avatarText: string;    // 아바타 이니셜 (예: 이)
  chips: string[];       // 기술 스택 칩 목록
}

export interface MyLinkData {
  user: UserProfile;
  links: LinkItem[];
}
```

### 6.2. 더미데이터 파일 (`src/data/mock-links.json`)
- **역할**: 마이링크 1단계의 공식 초기 시드(Initial Seed) 데이터 소스.
- **포함 데이터**:
  - 기본 사용자 프로필: `username: "07ez"`, `name: "이지환"`, `title: "주니어 웹 개발자"`, 5개 기술 스택 칩
  - 5개 링크 아이템:
    1. **GitHub 저장소** (`https://github.com/07ez`, 대표 링크, 활성)
    2. **프로젝트 & 포트폴리오** (`https://github.com/07ez?tab=repositories`, 일반 링크, 활성)
    3. **광운대 바이브코딩** (`https://github.com/07ez/mylink`, 일반 링크, 활성)
    4. **기술 블로그 (준비 중)** (`https://velog.io`, 일반 링크, 활성)
    5. **LinkedIn 프로필** (`https://linkedin.com`, 비활성 테스트용, `isActive: false`)

### 6.3. 백엔드 Mock API 엔드포인트 (`src/app/api/links/route.ts`)
- `GET /api/links`: `mock-links.json` 기반의 프로필 및 링크 전체 데이터 조회 (네트워크 통신 시연용)
- `POST /api/links`: 새 링크 추가 mock 응답
- `PUT /api/links`: 프로필 정보 또는 링크 목록 일괄 업데이트 mock 응답

## 7. 1단계 시연 시나리오 (Demo Script)

1. **초기 화면 확인**: `localhost:3000`에 접속하여 `src/data/mock-links.json` 기반으로 렌더링된 프로필과 링크 확인
2. **데이터 수정 시연**: 편집 모드에서 소개글 문구를 수정하거나 새 링크를 추가
3. **영속성 검증**: 브라우저를 새로고침해도 수정한 내용이 그대로 유지되는 모습 확인 (LocalStorage 연동 증명)
4. **리셋 시연**: '기본값 복원'을 눌러 `src/data/mock-links.json`의 초기 상태로 깨끗하게 원복
